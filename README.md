# poizon 选品引擎

> **一句话**：自动从品牌官网(现 LV)发现商品 → 判断哪些有潜力 → 和得物(POIZON)对比中国销量/竞争/利润 → 排出**最值得倒卖的品**。一套**可迁移**引擎(换品牌/平台只写适配器)。

面向使用者：韩国得物商家，做 LV 小皮具(钱包/皮带/鞋)韩国直邮倒卖。物流/清关/退税已通，**痛点是选品**。

---

## 🟢 给使用者：怎么用(不用懂代码)

### 你只需要提供这些
**首次(一次性):**
1. **一台韩国网络的 Mac + 装好 Claude Code**。（抓取必须用韩国 IP 过 LV 的 Akamai，且登录态在本机——所以在这台机器上运行，不是把 GitHub 扔给云端。）
2. **登录一次得物商家后台**：让 AI 驱动打开 `seller.poizon.com`，你用 **+82 手机验证码**登一次，登录态存本机 `tools/.seller_profile`，之后自动复用、免重登。
3. **确认成本参数**(`config/settings.yaml`)：买入折扣、物流单价、得物费率。**默认已按你的真实成本表填好**(采购系数 0.8891 = 退税 10/11 − 商品券 3% + 出口申报 1%)，变了再改。

**每次想选品，只要说一句:**
> "帮我选一波 LV 鞋 / 小皮具 / 腰带 的品"

可选附加条件：最低利润率、只看新品、预算多少件、某个类目。

### 你会拿到什么
一张**直发选品清单**（单模块，只做韩国 POIZON 直发），每行：货号 · 品名 · 中国30天销量 · **直发价₩** · **直发净利₩/¥** · **利润率** · **直发显示¥(买家看到的CNY)** · **月利润潜力** · 优先级(销量分层)。全量机会榜留档 Excel。

### AI 的记忆(为什么不用每次重讲)
AI 在这台 Mac 上有**持久记忆**(`~/.claude/.../memory`)，记着整套流程、工具、你的成本口径、历次发现和结论。**换一个新对话也记得**，不用重新解释。
> GitHub 存的是**代码**；**记忆、登录态、数据**都在你本机(不入库)。所以换机器要重新登录得物、重跑基线。

## 🔁 每次选品，AI 实际会跑的流程

> 原则：**便宜信号在前、贵操作在后**，每层大幅减量，不全量爬。

```
1. 得物需求(便宜, 批量)  seller后台按品牌导出 → 每个货号的 中国30天销量/成交均价/韩国卖家销量
        ↓ 筛:中国有销量 × 韩国卖家≈0(供给缺口)
2. LV 报价(中, 只给入围款) patchright 抓 LV 韩国现价 → 算净利/利润率(用你的成本模型)
        ↓ 排:机会分 = 0.45净利 + 0.35利润率 + 0.20需求
3. 出机会榜               该进哪些货，按机会分排序
```
**上新窗口(进阶主线)**：定期快照 LV 目录+得物，`diff` 出**新出现的货号=新品**，在 launch 窗口(价没被代购压下来前)抓得物价——这是利润最肥、最能跑赢欧洲代购的时机。基线已存 `data/snapshots/`，每隔几天跑一次 `tools/lv_new_arrivals.py snapshot` 即累积。

**实测重要结论**：LV **成熟热门款**(有 30 天销量的)已被竞争压到**薄利甚至负毛利**；真正赚钱的是**上新窗口**和**限量联名**。所以选品逻辑重心是"**抓供给缺口 + 上新窗口**"，不是扫成熟爆款。

## 🎯 选品决策框架（2026-08 起：单一直发模块）

**现货与直发已合并为一个模块**——现在只做 **韩国 POIZON 直发**（biddingType=27）。当前看不了国内得物立即变现信息 → **砍掉「立即变现」策略分支**，不再分现货/直发两条线。

- **卖价** = POIZON 直发最低价（₩）；**成本** = LV×0.8891（物流月付固定不计）；**技术费** 14% 封顶 ₩15k~45k
- **排序（赚钱第一性原理）= 直发月利润潜力 = 直发净利(₩→¥) × 中国30天销量**
- **销量分层只作优先级**（阈值 `tools/direct_select.py` 顶部可调）：销量好(≥10)→优先做 / 适中(3-9)→备选 / 不好(≤2)→仅毛利极高才做
- 命令：`python tools/direct_select.py`（单模块综合榜）；直发价由 `direct_board.py` 抓（open API bt=27，缓存 `data/direct_prices.json`）

## 📋 输出纪律：只做直发，清单按赚钱排

一次只能做这么多。每次选品清单只出 **Top N**（默认 20，能下手的最多 Top5-10），其余只留档。

- **主输出（单模块直发）**：`python tools/direct_select.py` —— 按 **直发月利润潜力 = 直发净利(₩→¥) × 中国30天销量** 排，每行：货号/名称/中国30天销量/**直发价₩**/**直发净利₩/¥**/**利润率**/**直发显示¥**/**月利润¥**/优先级。销量含 `<5` 估算的带 `*`。
- **SKU 细化**：直发价是逐 SKU 抓的（`direct_board.json` 的 `sku_detail`，含版本/尺码），同一货号不同版本/尺码净利差很大，别只按货号进货。
- **综合表单**（现货口径，备查）：`python tools/sku_comprehensive.py` —— 过滤极端尺码（鞋 KR235-275、皮带 85-100），综合分 = 0.40净利 + 0.30需求 + 0.30利润率。
- **爆款预测**：`python tools/predict_hits.py` —— 上新窗口 / 销量动量 / 联名限定 / 供给缺口四类信号。⚠️ 动量款多为负毛利（得物成交价 < LV 零售），爆款=需求端预测，利润靠买入折扣或上新窗口。
- **热门款待确认**：`python tools/hot_items.py` —— 中国销量最高款 + 各折扣档净利，去官网确认可买后再进榜。

## 🔀 履约方式：单一直发模块（2026-08 起）

**现货与直发已合并，只做韩国 POIZON 直发**（biddingType=27，韩国集货仓直发买家）。当前看不了国内得物立即变现信息，现货线暂不做。卖价基准 = 得物直发最低价（欧洲直发价）；出价可经 API 自动挂单/跟价（`direct-autonomous-bidding` + followType）。

- **取价**：开放 API `recommend-bid/price`（biddingType=27）逐 SKU 抓直发价 → `direct_board.py`（缓存 `data/direct_prices.json`，`--refresh-top N` 实时核最赚前 N 防陈旧假象）
- **出榜**：`python tools/direct_select.py`（单模块综合榜，按直发月利润潜力排）
- 历史现货工具（`lv_opportunity_board`/`top5_select`/`two_line`）保留备查，不再作为当前业务输出。

**直发线成本口径**（全程 KRW）：物流自有集团月付、每件不计；技术服务费 **14%，单笔封顶 ₩15,000~₩45,000**（LV 贵货 14% 早超顶、实际只收 ₩45,000≈2%，故直发费远低于现货）；成本 = LV含税价×0.8891。**只对标 POIZON 直发出价、按利润空间降序**。实测**直发线普遍比现货更赚**（费封顶）：如 1ACNYF 现货 15%→直发 24%、M13391 6%→14%——直发更适合高值 LV。
> ⚠️ 真实提交出价 = 上架真商品，务必人工确认后再调 API（不自动挂单/跟价）。

### 💡 直发定价逻辑（韩币出价 ↔ 得物 CNY 显示价，**不是汇率换算**）
这是直发线的核心，务必弄清：
```
① 你在 POIZON 出价(韩币 B)  →  ② 得物买家看到的人民币价 = (B / 得物汇率) × 1.091
                              ③ 你实收(韩币) = B − 技术费(14%,封顶₩15k~45k)
```
- **×1.091 = 跨境电商税**（直发口径 9.1%），所以买家看到的 CNY **比 B 直接换汇更高**——这不是普通汇率换算。
- **得物汇率 ≈ 199.2 KRW/CNY**（得物内部汇率，和 naver 的 ~225 不同；直发 CNY 显示价必须用 199.2）。
- **实例**（1AAREW 有盒 KR230，剩明洞 1 件）：出价 **₩2,050,000** → 实收 ₩2,005,000（−₩45,000 封顶费）→ 得物显示 **韩国直发 ¥11,226**；而国内顺丰 ¥11,989。你 ¥11,226 更便宜(7-10天到) → 抢国内单。
- **反算**：想让 CNY 显示价压到 ¥X（低于国内最低价抢单），出价 B = X × 得物汇率 ÷ 1.091，再略降。
- **⚠️ 出价 > ₩2,000,000** 触发一般贸易出口申报手续费（且视情况需报关授权书）——高值款要留意这笔额外成本/手续。
- 代码：`score.direct_net()` 返回 `cny_display`（得物显示价）+ `declare_needed`（是否超 200 万门槛）。参数在 `config/settings.yaml` 的 `direct`。

**③ 供给缺口线（抢先占位，低竞争）**：`python tools/supply_gap.py 30 3` —— 从**得物有 SPU（有真实中国销量、能挂链接）× 韩国本地卖家≈0** 的品里，按"有需求没人卖"排。这是可靠的抢占机会（真实数据，非盲盒）。排除异皮（鳄鱼/蜥蜴，跨境法律/CITES）+ 限定款（P 开头货号，难补货）。
> 💡 曾试过"得物完全没有"的品做上架机会，实测多为**老款死货/异皮/限定/难采**（得物没上是有原因的），且无销量数据无法判死活 → 已弃用，改为"供给缺口"（得物有需求但韩国没人卖）。`listing_opportunity.py` 保留备查。
> LV 逐尺码库存 + **首尔线下可买**（`lv_prices.mjs` 存 `locateInStore` + `skus[].csc_Sellable`）：Excel"首尔线下"列，看能否直接去首尔店拿货。
> ⚠️ **LV 库存数据是抓取时点快照，且 `storeSell` 只代表「官网可下单/可订」，不代表「店里现在有货」**——实测 8/5 抓取全 true，但官网 4/5 售罄。**官网实际库存才是准**。Excel 里「官网可订 N 尺码(实库以官网为准) / 官网不可订 / 未抓」：`N个尺码` = 可订的**尺码个数**（不是件数）。买货前以官网页面实际可购买为准，别信快照。

## 🧮 算法(选品核心，两步)

### ① 算净利(每个货号)
```
采购成本(CNY) = LV含税价(KRW) × (10/11 − 券率3% + 出口申报1%) ÷ 汇率  + 物流(中程×重量+顺丰+包装)
得物到手(CNY) = 得物结算价 × (1 − 技术费5% − 转账费1%) − 操作费¥38 − 邮补¥8.72
净利 = 到手 − 总成本      利润率 = 净利 / 总成本      (普通挂单/立即变现两场景取高)
```
口径：得物"过去30天成交均价"=卖家结算价(已核对，非买家含税)；跨境电商税(<5000→9.1%、≥5000→20%)买家承担。参数在 `config/settings.yaml`，已复现你的成本表(含税4.3M→成本¥17067、到手¥24467、净利43%)。

### ② 机会分
供给缺口(中国销量高×韩国卖家低)是前提；在此之上偏**毛利**排序：
```
机会分 = 0.45×净利 + 0.35×利润率 + 0.20×需求      (找冷门高毛利，不追爆款)
```
