# poizon 选品系统

> **一句话**：自动比对「LV 韩国买入价」和「得物卖出价 + 销量」，算清每个款每个码数的真实净利和热度，按一套加权评分排出**最值得倒卖的品**。

你是韩国的得物商家，做 LV 小皮具（钱包 / 皮带 / 鞋）的韩国直邮倒卖。物流、清关、退税、店铺都已打通——**唯一费脑子的是「进哪些货能赚钱、卖得快」**。这套系统把「选品」这件事自动化。

## 一、整体怎么跑（鸟瞰图）

```
        ┌─────────────── 取数 ───────────────┐
        │                                     │
  LV 韩国官网                            得物 App
  货号 → 含税价(KRW)                货号 → 近7天成交记录
        + 是否可售                    (逐 码数×包装：成交价 / 速度 /
        │                              想要 / 买家 / 竞价商家)
        │                                     │
        └──────────────┬──────────────────────┘
                       ▼
              ②  算净利（成本模型）
              每个「码数×包装」算出：净利¥ + 利润率%
                       ▼
              ③  打综合分（评分模型）
              先淘汰不赚钱/滞销，再按 热度+盈利−风险 加权
                       ▼
              ④  出榜  report/综合最优品榜单.xlsx
                 （按综合分从高到低，告诉你先做哪几个码）
```

**关联键 = LV 官方货号**（如 `1AK8BN` / `M4583`），两边都带这个号，是自动对比的基础。

## 二、算法（核心，分两步）

### 第 ① 步：算净利 —— 这一单到底赚多少？

对**每一个「码数 × 包装」**单独算（同款不同码、带不带盒，利润能差几千块）：

```
                    买入侧                                卖出侧
 ┌────────────────────────────────────┐   ┌──────────────────────────────────┐
 │ LV 含税价 (KRW)                      │   │ 得物成交价 (CNY，买家付的含税价)    │
 │   × (10/11  − 券率3% + 出口申报1%)   │   │   × (1 − 技术费 − 转账费1%)         │
 │   ÷ 汇率(实时, ≈224)                 │   │   − 操作费¥38 − 邮费补贴¥8.72       │
 │   = 采购成本 (CNY)                   │   │   = 得物到手 (CNY)                  │
 │ + 物流 = 中程(单价×重量)+顺丰50+包装20│   │                                    │
 │   = ───────────────── 总成本         │   │   ────────────────                 │
 └────────────────────────────────────┘   └──────────────────────────────────┘
                         │                              │
                         └──────────  净利 = 到手 − 总成本  ──────────┘
                                       利润率 = 净利 / 总成本
```

两种卖法各算一遍，**取利润高的那个**进榜：
- **普通挂单**：卖市场最低价，技术费 5%
- **立即变现**：卖最高求购价（≈市场价 × 94%），技术费降到 1%

> 关键口径：得物「成交价」是**买家付的含税价**；卖家结算价 = 含税 ÷ (1+跨境税)，税档按结算价 `<5000→9.1%`、`≥5000→20%`。成本系数 `10/11` 是退韩国 10% VAT。全部参数在 `config/settings.yaml`（实拍成本表校验过）。

### 第 ② 步：打综合分 —— 这几个赚钱的品，先做哪个？

**先硬过滤**（不进榜，直接淘汰）：

```
   净利 < ¥100  ？  ──► 淘汰（不值当）
   利润率 < 6%  ？  ──► 淘汰（资金效率太低）
   90天 0 成交  ？  ──► 淘汰（滞销，压货=死钱）
```

**幸存者**：把 8 个指标各自 [min–max 归一化] 成 0~1（在当前这批候选里的相对排名），再加权求和。
跨境倒卖资金有限、压货就是亏，所以「**卖得快**」和「**赚得多**」一样重要，最后用「卷不卷 / 价格稳不稳」扣风险分：

| 大维度 | 权重 | 细项（权重） | 含义 |
|---|---|---|---|
| 🔥 **流动性 / 热度** | **0.45** | 月化速度(.20) · 最近成交天数(.12) · 想要人数(.07) · 累计买家(.06) | 能不能快速卖出——**第一优先** |
| 💰 **盈利性** | **0.40** | 绝对净利(.22) · 利润率(.18) | 赚多少 + 资金回报率 |
| ⚠️ **风险**（负向，扣分） | **−0.15** | 竞价商家数(.08) · 成交价波动(.07) | 越卷、价越飘 → 分越低 |

```
综合分 = 0.45×流动性 + 0.40×盈利 − 0.15×风险      （范围 0~1，越高越优先做）
```

> 为什么用「相对排名」归一化：分数是**相对当前候选集**的，多个品一起跑才有区分度。想要/买家这类「商品级」指标在单一商品时会退化为中性 0.5，批量跑后自然拉开。代码：`src/scorer/heat.py`（榜单用）、`src/scorer/score.py`（主 pipeline）。

### 一个真实例子（榜首）

```
1AAREW 黑色 Trainer 41码 无盒
  近7天成交 30+ 笔(月化≈30) · 最近 1 天内成交 · 净利 ¥738 / 利润率 9%
  → 走量极快但利薄  → 综合分 0.684（榜首：流动性拉满）

1AK8BN 蓝色 Tilted 36码 原盒
  月化 15 · 净利 ¥1442 / 利润率 19%
  → 量中等但单笔利润最高  → 综合分 0.65（利润款）
```
一冲量、一赚利，是这批的双核心。**同款不同码净利能从 +¥3000 到亏损，务必挑码。**

## 三、数据从哪来（两条链路 + 现状）

| 链路 | 怎么取 | 现状 |
|---|---|---|
| **得物** 成交价 / 销量 | 得物有证书固定、无行情 API → **屏幕控制 Mac 版 App** 搜索→商品页→「最近购买」弹层，**本地 OCR 出文本**（省 token） | ✅ **已打通**。只采近 7 天成交（周销量信号）。工具 `tools/uia.py`（`ocr` 操作）+ `tools/ocr.py` |
| **LV 韩国** 价格 / 可售 | 官网有 Akamai 护盾 | 🔬 **研究中**。`pass-api` 已失效；真实接口走 Salesforce Commerce(`eco-as`)，需 patchright 真人化站内导航绕 Akamai。当前用**手填 LV 价**（`config/skus.csv`）兜底 |

> 得物侧为什么不用官方 API：官方 API 只有「最低求购价(ask)」，而「最近购买」是**真实成交价**，更准。详见 `docs/`。

## 四、快速开始

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env                                   # 代理、得物 AppKey/Secret
cp config/settings.example.yaml config/settings.yaml   # 成本参数 + 评分权重
cp config/skus.example.csv config/skus.csv             # 你主营的货号 + 成本/LV价

# 跑选品榜单（读 data/dewu_sales/*.json 的成交数据 + skus.csv）
python tools/run_sales.py        # → report/综合最优品榜单.xlsx
```

**爬得物某个货号的近期成交**（半自动，得物 App 需停在前台）：
```bash
.venv/bin/python tools/uia.py do "act;ocr"   # 截得物窗口→本地OCR→文本(零图片token)
```
